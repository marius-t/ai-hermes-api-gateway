# ai-api

A lightweight Koa.js API gateway that forwards user messages to a running
[Hermes agent](https://hermes-agent.nousresearch.com/) and returns only the
final output — no streaming, no intermediary steps exposed to the client.

## What it does

`ai-api` is a thin HTTP wrapper around a Hermes agent instance. It exposes
two endpoints:

| Method | Path        | Auth              | Description                                       |
|--------|-------------|-------------------|---------------------------------------------------|
| POST   | `/login`    | `API_TOKEN`       | Exchange a static API token for a session bearer  |
| POST   | `/message`  | `Bearer SESSION_TOKEN` | Forward a message to Hermes, return final output |
| GET    | `/health`   | none              | Liveness probe                                    |

### Request flow

```
Client → POST /login (API_TOKEN) → session bearer token
     → POST /message (Bearer SESSION_TOKEN) → Hermes agent (/v1/chat/completions)
     → { output: "..." }
```

The gateway handles retries, timeout, and error translation so callers don't
have to. Hermes itself does the heavy lifting — tool use, memory, skills,
cron, etc. — and `ai-api` just routes and authenticates.

## Architecture

```
src/
├── server.ts          # Koa app setup, middleware chain, port binding
├── config.ts          # Environment variable loading (dotenv)
├── hermes.ts          # HTTP client for forwarding to Hermes, with retry logic
├── schemas.ts         # Zod schemas for request body validation
├── middleware/
│   ├── auth.ts        # Bearer token check for /message
│   └── errorHandler.ts # Global Koa error handler
└── routes/
    ├── login.ts       # POST /login — token exchange
    └── message.ts     # POST /message — forward to Hermes
```

**Tech stack:** Koa 2, @koa/router, axios, zod, TypeScript 5.6 (strict mode).

## Getting started

### Prerequisites

- Node.js 20+ (this repo uses `ts-node-dev` and `tsc`)
- A running Hermes agent instance (default: `http://localhost:8000`)

### 1. Install dependencies

```bash
yarn install
```

### 2. Configure environment

Copy the example and fill in real values:

```bash
cp .env.example .env
```

Edit `.env`:

| Variable             | Required | Default            | Purpose                                   |
|----------------------|----------|--------------------|-------------------------------------------|
| `PORT`               | no       | `3000`             | Port the gateway listens on               |
| `API_TOKEN`          | **yes**  | —                  | Static token clients present at `/login`  |
| `SESSION_TOKEN`      | **yes**  | —                  | Bearer token issued by `/login`           |
| `HERMES_BASE_URL`    | **yes** | `http://localhost:8000` | Hermes agent HTTP API base URL       |
| `HERMES_TIMEOUT_MS`   | no       | `120000`           | Per-request timeout (ms)                  |
| `HERMES_RETRIES`     | no       | `2`                | Retry count on network failures           |
| `HERMES_API_KEY`     | **yes**  | —                  | Bearer token sent to Hermes for auth      |

### 3. Run in development

```bash
yarn start:dev
```

This starts `ts-node-dev` with `--respawn --transpile-only`, so it reboots on
file changes without a full type-check cycle.

### 4. Build for production

```bash
yarn build
```

Compiles TypeScript to `dist/` via `tsc`. Then start with:

```bash
yarn start
```

### 5. Test the health endpoint

```bash
curl http://localhost:3000/health
# {"status":"ok"}
```

### 6. Make a request

```bash
# Step 1: get a session token
SESSION=$(curl -s -X POST http://localhost:3000/login   -H "Content-Type: application/json"   -d '{"token":"your-api-token"}' | jq -r '.token')

# Step 2: send a message to Hermes
curl -s -X POST http://localhost:3000/message   -H "Authorization: Bearer $SESSION"   -H "Content-Type: application/json"   -d '{"message":"What is 2 + 2?"}'
# {"output":"4"}
```

## Project layout

- `src/` — all source code (TypeScript)
- `dist/` — compiled output (generated by `yarn build`)
- `node_modules/` — dependencies
- `.env` / `.env.example` — runtime configuration (`.env` is gitignored)
